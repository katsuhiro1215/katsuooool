# M5-3: 画像ツールの画面とリサイズ 設計書

ステータス: 実装済み（`docs/superpowers/plans/2026-10-11-m5-3-image-ui.md`）。本番反映は未実施。

作成日: 2026-10-11 / ブランチ: `feature/m5-3-image-ui` / 対象: ロードマップ M5 の第3段階（M5-1 上限、M5-2 圧縮方式は完了）

## 1. 目的

画像ツールを、iLoveIMG のように使いやすくする。広いドロップエリア、サムネイル一覧、右側のオプション欄、圧縮レベルの選択、リサイズの px/% 指定を、共通の部品として作り、まず**画像圧縮**と**画像リサイズ**を作り替える。PC での利用が中心。

## 2. 合意事項（オーナー確認済み）

- 作り替えの範囲：共通部品を作り、**圧縮とリサイズを先に**。形式変換・回転・OGP・色抽出は、後から同じ部品に乗せ替える（今回はやらない）。切り抜きと favicon は独自 UI のため対象外。
- 画面の流れ：**2段階で切り替える**。アップロード前は大きなドロップエリアだけ。ファイルを選ぶと、左にサムネイル一覧、右にオプション欄と実行ボタン。
- 結果の見せ方：**サムネイルをそのまま結果カードにする**。各サムネイルに「元サイズ → 後サイズ（削減率）」と個別ダウンロードを重ね、右は「まとめてダウンロード（ZIP）」と「設定を変えてやり直す」に切り替わる。
- リサイズ：ピクセルとパーセントの両方で指定できる。**拡大はしない**（元より大きい指定は、元のサイズに収めて知らせる）。
- 圧縮レベル（M5-2 でバックエンドは済み）を、画面から選べる：控えめ（画質そのまま）／推奨／強め。
- HEIC を圧縮・リサイズでも入力できる（出力は JPEG。HEIC は書き出せないため）。
- JPEG の結果に GPS が残る場合は、結果カードに注記する。

## 3. 現状

- 6つの画像ツール画面はそれぞれ約250〜470行で、ドロップエリア・ファイル名だけの一覧・ボタン・結果表示が、ほぼ同じ内容で重複している。
- 圧縮の結果は `input_bytes`・`output_bytes`・`reduction_percent`・`download_url` を返す。リサイズの結果は `width`・`height`・`download_url` だけで、サイズの情報がない。
- リサイズは、幅・高さの一方または両方を px で指定し、両方なら枠に収める。**拡大も許している**（上限は 8000px と出力2,500万画素）。
- 圧縮は HEIC を受け付けない（形式変換だけが受け付ける）。

## 4. 設計

### 4.1 画面の流れ

1. **アップロード前**: ページの見出しの下に、高さ `min-h-[60vh]` の大きなドロップエリア（点線の枠、「ここに画像をドラッグ＆ドロップ、または［ファイルを選択］」）。ページ全体のどこにドロップしても受け付ける。
2. **アップロード後**（1枚以上）: 2列。左にサムネイルのカード一覧（先頭に「＋追加」カード、各カードに×）。右にオプション欄（幅 320px）。モバイルは縦に積む（オプション欄は一覧の下）。上限（例: 「3 / 10枚」）を一覧の上に表示する。
3. **実行中**: サムネイルに処理中の表示（半透明の覆いとスピナー）を重ね、実行ボタンを無効にする。既存の `ProcessingBanner` を使う。
4. **実行後**: 各カードに結果を重ねる。
   - 成功: 「4.2MB → 1.1MB（74%削減）」と［ダウンロード］。JPEG で GPS が残っていれば「位置情報が残っています」の注記。
   - 失敗・拒否: 赤字で理由（現行のメッセージ）。
   - 右のオプション欄は「まとめてダウンロード（ZIP）」（2枚以上のとき）、合計（元の合計 → 後の合計）、「設定を変えてやり直す」（結果を消して、同じファイルのまま設定に戻る）に切り替わる。
   - 「すべて削除」で、アップロード前に戻る。

### 4.2 フロントの部品

`resources/js/components/image/` に共通部品を置く。

| 部品 | 役割 | 主な props / 返り値 |
|---|---|---|
| `composables/useImageBatch.ts`（フック） | ファイルの追加・削除、上限の判定、サムネイル用 URL の作成と破棄（`URL.createObjectURL`、削除・離脱時に `revokeObjectURL`）、送信（`axios.post`＋`FormData`）、結果の対応づけ、エラー解決 | 引数 `{ endpoint, maxFiles, accept }`。返り値 `files`・`results`・`phase`（`empty`／`ready`／`processing`／`done`）・`errorMessage`・`showPremiumUpsell`・`add`・`remove`・`clear`・`submit(extraFields)`・`resetResults` |
| `ImageDropzone.vue` | 大きなドロップエリア。ドラッグ中の強調。ページ全体のドロップを受ける | `accept`・`maxFiles`・`@files` |
| `ImageThumbGrid.vue` | サムネイルのカード一覧。状態（`ready`／`processing`／`success`／`failed`）ごとの重ね表示。HEIC はプレビューできないのでファイル名つきの代替アイコン | `items`・`@remove`・`@add` |
| `ImageToolShell.vue` | 前後の切り替え、2列の枠、ページ見出し。オプション欄はスロット（`#options`）、結果の合計はスロット（`#summary`） | `phase`・`title`・`description` |

- 判定の純粋な部分（上限で切り詰める、結果を元のファイルに対応づける、サイズの表記）は `resources/js/lib/imageBatch.ts` に関数として切り出し、Vitest で確認する。
- `ImageCompress.vue`・`ImageResize.vue` は、`#options`（圧縮レベル、またはリサイズの指定）と送信先だけを持つ薄いページになる。

### 4.3 オプション欄

- **圧縮**: 圧縮レベルのラジオボタン3つ。
  - 控えめ（`light`）：画質そのまま（JPEG・PNG は無劣化）
  - 推奨（`recommended`、既定）
  - 強め（`strong`）：画質が少し落ちる
- **リサイズ**: 切り替え［ピクセル｜パーセント］。
  - ピクセル: 幅・高さ（どちらか一方だけでもよい）。縦横比は常に保つ（枠に収める）。
  - パーセント: 1〜100 の数値（既定 50）。
  - 元より大きい値（ピクセル）は、元のサイズに収める。入力欄の下に「拡大はできません。元のサイズに収めます」と表示する。

### 4.4 バックエンド

- **リサイズ** `POST /image-resize`:
  - 新しい入力: `mode`（`pixel`／`percent`、省略時は `pixel`）、`percent`（`mode=percent` のとき必須、整数 1〜100）。`width`・`height` は `mode=pixel` のとき従来どおり（一方は必須）。
  - `ImageResizeService::resize` に拡大の防止を追加する。縮小率が 1 を超えるときは 1 に丸める（元のサイズ）。% は `percent / 100` を縮小率として使う。
  - 結果の JSON に `input_bytes`・`output_bytes`・`reduction_percent`・`clamped`（拡大指定を元のサイズに収めたか）を追加する。`width`・`height` は維持する。
- **HEIC の入力**（圧縮とリサイズ）: `image/heic`・`image/heif` を許可する。HEIC は、処理の前に JPEG（品質 92）へ変換してから、JPEG として扱う（出力名は `.jpg`）。画素数の確認は、形式変換と同じ（`getimagesize` が読めなければ Imagick のヘッダー読み取り）。この読み取りは、共通の `ImageDimensions::read()` に切り出す（形式変換の private メソッドから移す）。変換には Imagick が必要で、無い環境では「対応していない形式」として拒否する。
- **GPS の判定**: 圧縮の結果の JSON に `has_gps`（bool）を追加する。出力が JPEG で `exif_read_data` が使え、GPS の情報があれば true。読めなければ false。
- 圧縮の `level` は M5-2 のまま（`light`・`recommended`・`strong`）。

### 4.5 エラー・境界

- 枚数超過・サイズ超過・未対応形式・混雑（503）・レート制限（429）は、現行のメッセージ（`resolveErrorMessage`）を使う。
- 追加で選べる枚数が上限に達したら、「＋追加」カードを出さず、上限の表示を強調する。
- 上限を超える枚数をドロップしたときは、上限まで追加し、「一度にアップロードできるのは最大N枚までです」と表示する（現行と同じ）。
- 実行後にファイルを追加・削除したときは、結果を消して `ready` に戻る（古い結果が残らない）。
- ブラウザがプレビューできない画像（HEIC など）は、代替アイコン。サムネイルの生成に失敗しても、処理は続けられる。

### 4.6 コードの整理

- 圧縮・リサイズの旧ページの重複（ドロップ処理、エラー処理、結果表示）は、新しい部品へ移して削除する。他の画像ツールは変更しない（`resolveErrorMessage` は共通のまま）。

## 5. テスト

- Vitest: `imageBatch.ts` の関数（上限での切り詰め、結果の対応づけ、サイズの表記）、`useImageBatch`（追加・削除・フェーズの遷移・結果の消去）、`ImageThumbGrid`（状態ごとの表示、HEIC の代替アイコン）、`ImageDropzone`（ドロップ・選択・上限）。
- Pest: リサイズの `mode=percent`（1・50・100、範囲外は 422）、拡大しない（px・% とも）、`clamped`、結果の `input_bytes`・`output_bytes`、HEIC の圧縮とリサイズ（Imagick が無ければスキップ、Docker で確認）、圧縮の `has_gps`（GPS 付きのフィクスチャ）。
- ブラウザ（Playwright）: デスクトップ（1280・1920px）とモバイル（390px）で、アップロード前→後→実行後の3つの状態を撮って確認する。実画像（スクショ PNG、写真 JPEG、HEIC）で圧縮とリサイズを実行する。
- `composer test`、`npx vitest run`、`npm run lint`、`npm run types:check` を通す。

## 6. やらないこと

- 形式変換・回転・OGP・色抽出の作り替え（次の段階。部品はそのまま使える形にする）。切り抜き・favicon。
- 縦横比を保たない（引き伸ばす）リサイズ、1枚ごとの個別設定、プリセット（SNS 用サイズなど）。
- 結果のプレビュー画像のサーバー生成（サムネイルは、ブラウザ内のファイルから作る）。
- 圧縮方式の追加の調整（M5-2 の値のまま）。
