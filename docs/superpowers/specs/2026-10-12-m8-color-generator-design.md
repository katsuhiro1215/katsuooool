# M8: 配色ジェネレーター 設計書

ステータス: 設計（オーナーのレビュー待ち）

作成日: 2026-10-12 / ブランチ: `feature/m8-color-generator` / 対象: ロードマップ M8（色ツール強化）

## 1. 目的

色を「出す」だけのツールから、**Web サイトにそのまま使える配色を、選んで・確認して・持ち帰れる**ツールにする。

流れ：**気分を選ぶ → 色相の系統ごとのパレット一覧から選ぶ → 役割（ベース・メイン・アクセント・文字）を確認する → Web ページのひな形で実物を見る → CSS 変数などで持ち帰る**。

競合（Happy Hues、corto、Color Hunt、Huemint）は、「選ぶ」「基準色から作る」「実物で見る」「持ち帰る」のどれかに強いが、気分から入って全部をつなぐものはない。そこを狙う。用途は Web サイトの配色が中心（印刷物・ロゴは対象外）。

## 2. 合意事項（オーナー確認済み）

- 新画面 1 つ「配色ジェネレーター」（`/color-generator`）に、旧「色の組み合わせ」「カラーパレット」を**統合**する。旧 URL は新画面へ 301 転送する。
- 生成は**ブラウザ内の計算のみ**（外部 API・LLM・DB なし。費用ゼロ）。後から「おすすめ」を固定で足せる作りにする。
- 気分は 10 個：やさしい／あたたかい／信頼・誠実／爽やか／力強い／上品・大人／元気・ポップ／自然・ナチュラル／モダン・クール／ダーク。
- 基準色から作るモードも同じ画面に入れる（配色パターン：類似・補色・分割補色・三色・同系色）。
- 結果は URL に入れ、共有・再読み込みで同じ画面になる。

## 3. 現状

- `ColorScheme.vue`（138行）は基準色から色相をずらす 5 種の配色を出すだけ。`ColorPalette.vue`（145行）はランダム 5 色（ロック可）。どちらも下部に DB の「例」ギャラリー（`ColorExample`）とコピー計測がある。
- `lib/color.ts` に、`parseHex`・`hslToHex`・`hexToHsl`・`contrastRatio`・`rotateHue` などがある（再利用する）。
- 色ツールは `config/tools.php` の `category => 'color'`。サイドバーのカテゴリ件数は `toolNav` から自動で出る。

## 4. 設計

### 4.1 生成ロジック（`resources/js/lib/palette/`、純粋関数・Vitest で確認）

| ファイル | 役割 |
|---|---|
| `moods.ts` | 10 個の気分の定義。各気分は、彩度の範囲・明るさの範囲・色相のずらし方（5 色の型）・ダーク／ライトの別を持つ |
| `generate.ts` | `generatePalettes(mood, hueFamily)`：気分と色相系統から複数のパレットを返す。`fromBase(hex, pattern)`：基準色と配色パターンから返す。**同じ入力は同じ結果**（乱数なし。色相を等間隔に刻み、彩度・明るさは気分の範囲内で段階を付ける） |
| `roles.ts` | 5 色にベース（背景）・サブ背景・メイン・アクセント・文字を割り当てる。文字色は背景に対し AA（4.5:1）を満たすよう明るさを調整する。割合の目安 60/25/10/5 |
| `export.ts` | CSS 変数・Tailwind（`theme.extend.colors`）・HEX 一覧の文字列を作る |

- 色相の系統は 8 つ：赤・橙・黄・緑・青緑・青・紫・桃。気分によっては該当しない系統がある（例：ダークは全系統で生成するが、自然は赤・桃の行を出さない）。行の有無は気分の定義で決める。
- 1 つの気分×系統あたり、パレットは 4 つ程度（型の違い）。合計で 1 つの気分につき 20〜30 パレット。
- 既存の `lib/color.ts` を再利用し、色空間の変換は重複させない。

### 4.2 画面

- `pages/ColorGenerator.vue`（薄いページ）と、`components/color/` の部品：
  - `MoodSelector`：気分ボタン 10 個と、基準色モードの入口（色入力＋配色パターンの選択）。
  - `PaletteFamilyList`：系統ごとの行にパレットカードを並べる。
  - `PaletteCard`：5 色の帯。選択状態を持つ。
  - `PaletteDetail`：役割・割合・コントラスト判定（AA/AAA）・コピー（HEX 個別、CSS 変数、Tailwind、HEX 一覧）。
  - `SitePreview`：Web ページのひな形（ヘッダー、ヒーロー、カード、ボタン、フォーム）。ライト／ダークの切り替え。選んだパレットの役割を CSS 変数で当てる。
- PC は気分とパレット一覧を上に、詳細とプレビューを下に置く（または右の列）。モバイルは縦に積む。
- 状態は URL に入れる：`?mood=gentle&hue=blue&p=2`、基準色モードは `?base=2f6f8f&pattern=analogous`。入力に応じて `history.replaceState` で更新する（履歴を積み過ぎない）。不正な値は既定の気分（やさしい）に戻す。
- 計測：気分または基準色を選んだとき、`POST /color-generator/track` を 1 回送る（デバウンス。失敗は無視）。既存の `TrackedToolController` を使う。

### 4.3 バックエンド・ルーティング

- `ColorGeneratorController`（`TrackedToolController` を継承。例ギャラリーの機能は付けない）、routes に `GET /color-generator`、`POST /color-generator/track`。
- `config/tools.php`：`color-generator` を追加（カテゴリ color、名前「配色ジェネレーター」）。`color-scheme` と `color-palette` を一覧から外す。
- 旧 `/color-scheme`・`/color-palette` の `GET` は 301 で `/color-generator` へ転送する。旧 POST（track／examples copy）の route は、旧ページを見ていた人のために残す（ページ自体は消すので事実上呼ばれない。残すか消すかは実装時に判断し、消す場合は 404 でよい）。
- 旧ページ `ColorScheme.vue`・`ColorPalette.vue` とそのテストは削除する。`ColorExample` のモデル・DB・`ColorGradient` の例ギャラリーは、そのまま残す。

### 4.4 エラー・境界

- 基準色の入力は HEX（`#` 有無・3桁/6桁）を許容し、不正なら直前の値を保つ。
- どの気分・系統でも、文字色は背景に対して 4.5:1 以上になる（保証できない組み合わせは、文字色を白または黒に倒す）。
- クリップボードが使えない環境では、値が見える状態のままにする（現行と同じ）。
- URL に未知の気分・系統・パターンが入っていたら、既定に戻す。
- プレビューのダーク版は、選んだパレットが暗い気分でも明るい気分でも破綻しない（背景と文字を入れ替えるのではなく、ダーク用のベース色を別に算出する）。

## 5. テスト

- Vitest：`moods`（全気分が必須項目を持つ）、`generate`（同じ入力で同じ結果、色の範囲、色数 5、重複しない）、`roles`（全生成パレットで文字×背景が 4.5:1 以上）、`export`（出力文字列の形）、URL の読み書き（不正値の補正）、`MoodSelector`・`PaletteCard`・`PaletteDetail` の表示と操作。
- Pest：`/color-generator` が描画される、`POST …/track` が記録される、旧 `/color-scheme`・`/color-palette` が 301 で転送する、ツール一覧に新ツールがあり旧ツールがない。
- ブラウザ（Playwright）：1280px・390px で、気分の選択→一覧→詳細→プレビュー→コピーを撮って確認する。URL を直接開いた再現も確認する。
- `composer test`、`npx vitest run`、`npm run lint`、`npm run types:check` を通す。

## 6. やらないこと

- AI／外部 API による生成、パレットの DB 保存、ユーザーごとの保存・お気に入り（将来の検討）。
- 画像から色を抽出（既存ツールのまま）。グラデーション・コントラスト・色変換の作り替え。
- 印刷物・ロゴ向けの配色。
- 厳選した「おすすめ」パレット（後から足せる作りにするが、今回は入れない）。
