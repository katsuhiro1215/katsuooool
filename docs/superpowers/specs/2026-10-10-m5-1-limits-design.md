# M5-1: 画像ツールの上限の見直し 設計書

作成日: 2026-10-10 / ブランチ: `feature/m5-1-limits` / 対象: ロードマップ M5 の第1段階（M5-2 圧縮精度、M5-3 画面とリサイズは別設計）

## 1. 目的

画像ツールの枚数上限を引き上げつつ、**JPEG・PNG を確実に処理できる**ことを最優先にする。Premium 公開前でも、本番の `app` コンテナがメモリ不足で落ちないようにする。

## 2. 合意事項（オーナー確認済み）

- 枚数：無料 **10枚**、Premium **20枚**（JPEG・PNG・WebP の圧縮・変換・リサイズ・回転など）。
- **AVIF は負荷が高いので枚数を絞る**。Premium 公開前でも使えるよう、無料も少数だけ許可する。
- JPEG・PNG はよく使われるので、確実に対応する。
- 1ファイルのサイズ（10MB）は、測定結果を見て再提案する。それまでは変えない。
- iPhone の写真（HEIC）を扱えるようにする（オーナーが実際に使っていて必要を感じた）。
- 慌てず、1つずつ進める。

## 3. 測定結果（2026-10-10、本番と同じイメージ、CPU 2・メモリ 512MB、1枚ずつ）

| 画像 | 処理 | 時間 | ピークメモリ |
|---|---|---|---|
| 12MP | JPEG圧縮 | 0.4秒 | 213MB |
| 12MP | WebP変換 | 2.0秒 | 447MB |
| 12MP | PNG変換 | 14.1秒 | 533MB |
| 12MP | AVIF変換 | 5.3秒（実写風では15.6秒） | 456MB |
| 25MP | JPEG圧縮 | 0.6秒 | 400MB |
| 25MP | WebP変換 | 10.2秒 | 533MB |
| 25MP | AVIF変換 | 18.2秒 | 539MB |
| 25MP | PNG変換 | **強制終了（OOM、exit 137）** | 512MB超 |

- テスト画像は滑らかな合成画像（plasma）。実写の写真はさらに重くなる傾向がある。
- 今の本番でも、2,500万画素いっぱいの画像1枚で `app` コンテナが落ちる可能性がある（M2 の「数十MB」は小さい画像での値）。
- 20枚を AVIF で処理すると、300秒前後。Caddy の `read_timeout 120s` を超える。

## 4. 設計

### 4.1 上限の設定ファイル化

- `config/image_tools.php` を新設する。値は次のとおり。
  - `max_files`: `free` 10 / `premium` 20
  - `avif_max_files`: `free` 2 / `premium` 5（AVIF を出力する変換のみ。画像形式変換）
  - `max_file_bytes`: 10MB
  - `max_pixels`: 25,000,000（4.2 の結果で見直す）
- 7つのコントローラー（圧縮・形式変換・リサイズ・回転・OGP・色抽出ほか）の重複した定数を、この設定の参照に置き換える。
- 画像形式変換で出力形式が AVIF のときは、`avif_max_files` を適用する。画面にも、その上限を表示する。

### 4.2 メモリ対策（最優先）

目標: **2,500万画素の JPEG・PNG・WebP の処理が、`mem_limit: 512m` で強制終了しない**。

- Imagick のリソース制限（メモリ・マップ・ディスク退避）を、アプリ起動時に設定する。
- 設定値は実測で決める。効果が足りなければ、次の順で採用する。
  1. 画素数の上限を引き下げる（候補: 1,600万）
  2. `app` の `mem_limit` を引き上げる（本体を巻き込まない範囲。インスタンスの空きは約2GB）
- **同時実行の制限**: 重い画像処理は、同時に2件までに制限する（ファイルロックによる枠）。枠が埋まっているときは、利用者に「混み合っています。少し待ってから再実行してください」と表示する。php-fpm の同時リクエストで、メモリが重なって `app` が落ちるのを防ぐ。測定の結果、1リクエストが十分に小さくなれば、この制限は見送る。

### 4.3 時間の対策

- 内側 Caddy の `read_timeout` を 120s から 300s に、PHP の `max_execution_time` も同じ値にそろえる。
- AVIF の枚数制限（4.1）で、最悪ケースの所要時間を 300 秒内に収める（AVIF 5枚×最大約20秒＝約100秒）。

### 4.4 サーバー設定

- `post_max_size` を 110M から 230M に、内側 Caddy の `request_body max_size` を 110MB から 230MB に、`max_file_uploads` を 20 から 25 に引き上げる。20枚×10MB＝200MB にゆとりを持たせた値。
- 本体 Caddy にはサイズ上限がないので、本体側の変更は不要。

### 4.5 HEIC（iPhone の写真）の入力対応

- 確認済み（2026-10-10）：本番イメージ（libheif・libde265）は HEIC を読める。4000×3000 の HEIC を JPEG 0.2秒・WebP 1.0秒・PNG 8.4秒、ピークメモリ 315MB で変換できた。MIME は `image/heic`。
- **画像形式変換**の入力に `image/heic`・`image/heif` を追加する（出力は JPEG・PNG・WebP・AVIF）。HEIC は書き出せない（エンコーダーがない）ため、出力形式には含めない。
- 上限（枚数・10MB・画素数）は他の形式と同じ。48MP の HEIC は画素数の上限を超えるため、拒否して理由を案内する。
- 向き（EXIF Orientation）と色（Display P3）が、変換後も正しく反映されることをテストで確認する。
- 圧縮・リサイズ・回転・切り抜きでの HEIC 入力（出力は JPEG になる）は、画面の設計を行う M5-3 で扱う。

## 5. やらないこと

- 1ファイルのサイズ（10MB）の引き上げ（測定後に再提案）。
- 圧縮方式の変更（cwebp・pngquant の採否は M5-2）。
- 画面の作り替え、リサイズの px/% 指定（M5-3）。
- 非同期キュー化（同期処理の方針は維持）。

## 6. エラー・境界

- 枚数超過: これまでどおりバリデーションエラーで案内する。AVIF のときは、AVIF 用の上限をメッセージに出す。
- 処理中のメモリ不足・時間切れ: 該当ファイルを失敗として扱い、他のファイルは続ける（現行の「個別失敗はスキップ」方針）。コンテナが落ちる事態を避けるのが目的。
- 同時実行の枠が埋まっている: 一時的な混雑として案内する（4.2）。
- 画素数の超過: これまでどおり拒否して案内する。

## 7. テスト

- Pest: HEIC を入力にした変換（JPEG・PNG・WebP・AVIF）、向きの反映、48MP の拒否。
- Pest: 設定値で上限が変わること（無料10・Premium20・AVIF 2/5）、AVIF 出力のときの枚数制限、既存の枚数テストを新しい値に更新。
- 本番イメージでの負荷確認（ローカル Docker、CPU 2・メモリ 512MB）: 25MP の JPEG・PNG・WebP が強制終了せず、AVIF 5枚が 300 秒以内に終わること。2リクエスト同時でもコンテナが落ちないこと。
- `composer test` を通す。

## 8. 本番反映

- フロントエンドは変えないが、`app`・`scheduler` と内側 Caddy の設定（`katsuooool-web`）が変わるため、3つとも再作成する。本番の手順は `projects/katsuooool/CLAUDE.md` の「本番反映の手順」に従う。

## 9. 実測にもとづく決定（2026-10-10、実装時）

- Imagick のリソース制限：メモリ128MB・マップ256MB・ディスク2GiB・スレッド2 を採用。25MP の PNG 変換は、制限なしで強制終了、制限ありで約23秒・ピーク81〜97MB で完了。WebP 変換 4.5秒・213MB、JPEG 圧縮 0.7秒・114MB、リサイズ・回転 100MB 以下。
- AVIF のメモリは Imagick の制限の外（libaom）で、画素数にほぼ比例（4MP 182MB、8MP 316MB、12MP 442MB、16MP 以上 約538MB）。**AVIF 専用に800万画素の上限**を設けた。
- PNG 圧縮の256色化は画素数に比例して遅い（4MP 20秒、8MP 43秒、12MP 129秒、25MP 265秒）。**400万画素までに限定**。メモリ枠を広げても速くならない。
- `app` の `mem_limit` を **512m から768m に引き上げ**。AVIF（800万画素）2件の同時実行でコンテナ全体のピークが627MBになるため。
- 同時実行の制限（4.2）を実施。ルートのミドルウェアで、重い処理を同時に2件までにする。
- 未対応の注意: 25MP の PNG への変換は約23秒/枚。Premium で20枚をすべて 25MP にすると 300 秒を超える。実際の利用では考えにくいが、超えた場合は時間切れになる。
