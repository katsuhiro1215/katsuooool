# M9-2: UI パターンのデータ拡充 設計書

ステータス: 実装済み（オーナー承認済み。本番反映は未実施。実装計画は `docs/superpowers/plans/2026-10-12-m9-2-pattern-data.md`）

## 1. 目的

UI パターン集のうち、ギャラリーが空のカテゴリ（モーダル・トースト・ローディング・スケルトン・ヘッダー・フッター・フォーム 5 種）と、件数の少ないページネーションを埋める。競合に対する差別化は「動くコードをそのままコピーできること」なので、まず数と質をそろえる。

## 2. 合意事項（オーナー確認済み）

- 私（Claude）が案を作り、まず今回の案で進める。UI は増えるものなので、必要なら後から追加する。
- 全件を**無料**にする（`is_premium` は false）。Premium の線引きは後で決める。
- 管理画面からの手入力は今までどおり使える。取り込みは既存の行（本番のボタン 49・カード 24・ページネーション 3 など）を壊さない。
- 本番反映は、M9-1 とあわせて後でまとめて行う。

## 3. 現状

- 本番のギャラリーの件数：ボタン 49、カード 24、ページネーション 3、ほか 11 カテゴリは 0。登録はすべて管理画面の手入力。
- モデル `UiPatternSnippet`（`category`・`title`・`html`・`css`・`is_premium`・`copy_count`）。カテゴリの許可リストは `UiPatternSnippet::CATEGORIES`。
- プレビューは M9-1 で、実寸で測って枠（高さ 224px）に収める方式になった。

## 4. 設計

### 4.1 データの入れ方

- パターンは JSON ファイル `database/data/ui-patterns/<カテゴリ>.json` に置く（1 ファイル＝1 カテゴリ。配列の各要素が `{"title","html","css"}`）。
- 新しい artisan コマンド `ui-patterns:import {category?}` が取り込む。
  - カテゴリを省略すると、`database/data/ui-patterns/` のすべてのファイルを処理する。
  - 同じ（カテゴリ、タイトル）の行があれば、`html` と `css` だけを更新する。なければ追加する（`is_premium` は false、`copy_count` は 0）。
  - 既存の行の `copy_count`・`is_premium` は変えない。管理画面から登録された、JSON にないタイトルの行は触れない。
  - 何度実行しても結果は同じ（冪等）。実行後に「追加 N 件・更新 N 件」を表示する。
- 本番では、反映のあとに `docker compose -f compose.prod.yaml exec app php artisan ui-patterns:import` を 1 回実行する。ファイルはイメージに入る（`database/` はコピーされる）。

### 4.2 品質の決まり（自動テストで全ファイルを検査）

`tests/Feature/UiPatternDataTest.php` が、`database/data/ui-patterns/*.json` のすべてを検査する。

- ファイル名が `UiPatternSnippet::CATEGORIES` のどれかと一致し、各要素に `title`・`html`・`css`（空でない文字列）がある。
- タイトルは「日本語名（English Name）」の形式で、255 文字以内。同じファイル内で重複がない。
- 外部への依存がない：URL は `placehold.co` だけ許す。`<script>`、`position: fixed`、`vh`/`vw` 単位、`@import` を含まない。
- 管理画面の入力規則を満たす（カテゴリが許可リストにある）。
- カテゴリごとの最低件数（下の表）を満たす。

### 4.3 作り方の決まり

- 1 パターン＝自己完結した HTML と CSS（クラス名は、そのパターン内で完結。ほかのパターンと共有しない）。
- モーダル・トーストは、画面に固定せず、部品そのもの（ダイアログの箱、通知の箱）を静的に置く。必要なら背景用の枠（`position: relative`）に入れる。
- 画像は `https://placehold.co/…` のみ。アイコンは絵文字・HTML 実体参照・CSS の図形（外部のアイコン集は使わない）。
- 動きは CSS のみ（アニメーション、`:hover`、`:focus`、`:checked`）。JavaScript は使わない。
- 色は、各パターンの内側で完結。文字はコントラスト比 4.5:1 以上を目安にする。
- 幅は、プレビューの枠（約 350px。ヘッダー・フッターは横幅いっぱい）で見やすい大きさにする。

### 4.5 表示

- ヘッダー・フッターのページは、M9-1 で 1 列にした。ほかは 3 列のまま。
- カテゴリのページ（`/ui-pattern-*`）は、データを入れるだけで表示される。画面の変更は、確認で見つかった崩れの修正に限る。

## 5. テスト

- Pest：`ui-patterns:import` の追加・更新・冪等性、`copy_count`・`is_premium` を壊さないこと、JSON にない行に触れないこと、不正な JSON のエラー表示。
- Pest：`UiPatternDataTest`（上の決まりをすべてのファイルに対して）。
- ブラウザ（Playwright）：各カテゴリのページを、取り込んだローカル DB で開き、全件が切れず読めることを撮って確認する。

## 6. やらないこと

- Premium 限定の印付け、JavaScript が必要なパターン（開閉メニューの動きなど）、新しいカテゴリの追加（M9-3）、管理画面の変更、並び替え・絞り込み。

## 7. 本番反映

- フロント・PHP のコードとデータが変わる。`app`・`scheduler`・`katsuooool-web` の 3 つを再作成（M9-1 とまとめて）。反映後、サーバーで `ui-patterns:import` を 1 回実行する。DB のスキーマ変更はなし。
